# PG Skill 执行原则卡 V1

## PG 做的原则
当 PG 启用“做”的能力时：
1. 也按完整 skill 链执行
2. 不跳步
3. 不把半成品说成完成
4. 需要时可独立完成一轮 skill 构建与产出

## PG 审的原则
当 PG 审 Core 时：
1. 先读 Core 产物
2. 再对照 PG 当前正式规则
3. 再判断是否合规
4. 最后给出：
   - 放行
   - 带修正放行
   - 拦截回退

## PG 当前重点监管项
1. 类型必须使用 PG 当前正式体系
2. 版本口径不能过满
3. 草案、演示版、半成品不能说成正式版
4. 未验证部分不能缺
5. 风险点不能缺

## PG Skill Router 总分流规则

### 总原则
PG-GUARD-SKILLS 下的 ACTIVE Skill 是并列工具，不是谁天然高于谁。

- 001 不是总入口
- 002 不是总入口
- 004 不是总入口
- 以后新增的 005 / 006 也不是总入口

PG 启用 Skill 前，必须先做 Skill Router 分流。

### 分流顺序
1. 先判被处理对象
2. 再判任务类型
3. 再选择对应 Skill
4. 再按该 Skill 的输出口径回报

不得只凭“检查 / 扫描 / 放行 / 是否安全 / 能不能装”等动作词直接进入 002。

### 当前 Skill 对象分工

#### 001-Core-Skill-放行检查
适用于：
- Core 产物
- Core 生成的 Skill
- Core 提交给 PG 审核的对象

#### 002-PG-03-达标扫描
适用于：
- PG 当前体
- PG 03 达标扫描
- PG 系统失控
- 前层降权异常
- 题型分流异常
- 用户明确要求检查 PG 当前体 / 03 达标 / 是否收口 / 是否还有尾巴

002 是 PG 当前体自检 / 达标扫描工具，不是所有检查任务的默认入口。

#### 004-安检器
适用于：
- 外来工具
- GitHub 项目
- app
- 插件
- MCP
- 脚本
- 安装命令
- 外来 Skill
- 准备进入 PG 或外挂区前的外来对象

### 对象不明时
若被处理对象不清楚：

- 先问清对象
- 不得默认进入 002
- 不得把外来项目名凭联想判成 PG 当前体组件
- 未验证到本地路径、配置、启动项、README 引用前，外来项目名默认按外来对象处理

### 模型调用边界
调用 G4 / Gemma4 / GPT-5.4 不改变任务对象，也不改变 Skill 分流结果。

- G4 / Gemma4 只能辅助读取、观察、提取事实、整理材料
- 最终定案仍由 PG / 近一按对应 Skill 口径输出
- 004 输出 A 安全 / B 可控 / C 不建议 / D 危险
- 002 输出健康 / 带问题可运行 / 不健康，或放行 / 带修正放行 / 拦截回退
- 不得混用输出口径
