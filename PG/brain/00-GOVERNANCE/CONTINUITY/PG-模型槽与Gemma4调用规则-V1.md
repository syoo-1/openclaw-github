# PG-模型槽与 Gemma4 调用规则 V1

- 英文 ID：`openai/gpt-5.4`

### qwen2.5:3b
- 退出 PG 主链
- 不进 `primary`
- 不进 `fallback`
- 不做传声筒
- 不做前层候选
- 不碰主脑、分流、模型切换、长期记忆

## 二、核心分工

- PG / 近一掌主权；Kimi 是默认主判模型位，负责判题、分流、组织判断与结果回收。
- Gemma4 / oMLX 优先承担低成本多模态、材料加工、观察、初筛、整理、翻译、摘要等执行任务。
- GPT-5.4 只承担高风险、高价值、复杂推理、复杂代码、专家复核等高阶补强任务。
- qwen 退出 PG 主链。

一句话：

> Kimi 掌判题和定案；Gemma4 / oMLX 优先干活；Kimi 必要时亲自上阵；GPT-5.4 只做高阶补强；qwen 属历史旧口径。

## 二A、模型调用与任务分流不得混杂

模型调用不是任务本身。

PG / 近一在调用 Gemma4 / G4 / oMLX / GPT-5.4 前，必须先完成：

1. 判明用户任务
2. 判明被处理对象
3. 判明应进入的 Skill / 规则路径
4. 判明该模型在本任务中的辅助职责

模型调用必须服从任务对象和分流结果，不能反过来改变任务对象。

硬规则：

- 调用 Gemma4 / G4 不等于进入 PG 当前体检查
- 调用 Gemma4 / G4 不等于进入 002-PG-03-达标扫描
- 调用 Gemma4 / G4 不得把外来对象改写成 PG 当前体
- 调用 Gemma4 / G4 不得输出放行、带修正放行、达标等主判结论
- 外来工具 / GitHub 项目 / app / 插件 / MCP / 脚本 / 安装命令 / 外来 Skill 的检查任务，仍按 004-安检器口径执行
- PG 当前体 / 03 达标 / 系统失控 / 前层降权异常 / 题型分流异常，才允许进入 002-PG-03-达标扫描

标准回报顺序：

1. 本次任务：XXX
2. 被处理对象：XXX
3. 本次分流：004 / 002 / 其它
4. 调用模型：Gemma4 / G4 / GPT-5.4 / 不调用
5. 模型职责：只读观察 / 提取事实 / 整理材料 / 专家复核
6. 最终定案：由 PG / 近一按对应 Skill 口径输出

## 三、全模态任务流程

老林发来全模态材料后：

1. PG 壳接收材料。
2. Gemma4-e4b 只做感知转换。
3. Gemma4 输出固定任务包。
4. Kimi 接收任务包。
5. Kimi 判题、分流、决定是否派 Core。
6. Core 执行后回交。
7. PG / 近一在 Kimi 默认主判模型位组织下审核后回报老林。

## 四、Gemma4 权限边界

Gemma4 允许：

- 观察
- 提取事实
- 标注不确定点
- 生成任务包

Gemma4 禁止：

- 直接派 Core
- 判断主线
- 判断阶段
- 判断身份
- 判断系统边界
- 判断是否达标
- 判断是否放行
- 修改系统
- 写入长期记忆
- 修改模型默认配置

## 五、模型切换硬闸

- 用户说“切换到 GPT / qwen / Kimi”，默认是临时查看或手动热切，不是永久修改默认模型。
- PG 不得执行 `openclaw models set ...`
- PG 不得执行 `openclaw model set ...`
- PG 不得执行任何会改写 `openclaw.json` 或 `primary` 的模型切换命令。
- 只有老林明确说“永久修改默认模型”，才允许讨论修改配置。
- PG 默认主前台必须保持：`moonshot/kimi-k2.5`

## 模型分工正式口径 V2

### 总原则

当前模型分工以“压复杂、提可靠”为优先。

Kimi 是默认主判、分流、执行监督和最终定案层。  
Gemma4 不再作为默认“扛大梁”的执行层。  
GPT-5.4 作为高阶后盾，不作为日常默认执行层。

### Kimi 职责

Kimi 默认负责：

- 判题
- 分流
- 规则边界判断
- 安检定级
- 安装授权检查
- 外挂区管理
- 文件移动 / 规则修改 / shell 执行监督
- 最终定案与回报

文本类、规则类、安检类、安装类、外挂区管理类任务，默认由 Kimi 处理。

### Gemma4 职责

Gemma4 优先作为本地多模态承接层。

适用范围：

- 图片观察
- 截图观察
- 视频关键帧观察
- 多模态材料初步整理
- 用户明确要求调用 G4 / Gemma4
- Kimi 判断确有必要，并先说明调用原因

Gemma4 不负责：

- 最终定案
- 安检 A/B/C/D 最终评级
- 是否安装
- 是否进入外挂区
- 是否装进系统
- 是否接入 PG / 新 Core 正式运行体
- 主权、阶段、边界、达标、放行判断

### GPT-5.4 职责

GPT-5.4 是高阶后盾。

适用范围：

- 高风险安全判断
- 复杂代码审查
- Kimi 判断与规则冲突
- 分歧复核
- 疑难问题
- 用户明确要求专家补强

默认不自动调用 GPT-5.4。  
高风险场景应先建议是否调用 GPT-5.4 复核，等待老林确认。

## 自动触发机制 V1

### 1. 普通文本任务

默认 Kimi。

不自动触发 Gemma4。  
不自动触发 GPT-5.4。

### 2. 图片 / 截图 / 视频关键帧

自动触发 Gemma4 做观察材料包。

Gemma4 只输出观察材料，不做最终裁定。  
Kimi 根据材料包和正式规则做最终判断。

### 3. 安检 / 安装 / 外挂区 / 文件移动 / 规则修改

默认 Kimi。

不自动触发 Gemma4。  
如任务中包含截图、界面图片、视频帧，再触发 Gemma4 做观察材料包。

### 4. 高风险场景

高风险场景自动提示是否需要 GPT-5.4 复核，但不自动执行。

高风险包括：

- 装进 PG / 新 Core 正式系统
- 修改启动链 / LaunchAgent
- 大范围删除文件
- 接入 PG 正式运行体
- 接入新 Core 正式运行体
- 复杂代码安全审查
- 安装脚本不可读或风险不明
- Kimi 判断与现行规则冲突

### 5. 用户明确要求调用模型

用户明确说“调用 G4 / Gemma4”时，可以调用 Gemma4。  
Gemma4 仍不得定案。

用户明确说“让 GPT-5.4 复核”时，可以调用 GPT-5.4。  
GPT-5.4 输出作为高阶复核意见，最终仍由当前主判链按规则收口。
