# 00-最终七件套收口验收卡

## 定位

本卡用于检查系统建设 / 减重 / 收口任务是否真正闭环。

本卡不是新规则总纲，而是最终验收清单。

任何阶段收口时，必须区分：

- 本轮闭环完成
- 全部系统性任务完成
- 仍有尾巴
- 下一步优先项

不得把局部完成说成全部完成。

---

- 不合格时先查 diff、log、tag
- 不直接删除当前成果

- 回滚后必须重新跑 safety-check 与 PG / Core 固定验收

---

### 6. 哪些内容允许写回母本

允许写回：

- 已验证的当前现实
- 已验证的入口规则
- 已验证的验收题
- 已验证的同步 / 回滚 / 非入口边界
- 经筛选的长期原则

不允许直接写回：

- 旧运行现场原文
- 退役区旧口径
- 暂存池未经筛选材料
- 模型临时输出
- 未验收的解释性规则
- 一次性排障过程

验收标准：

- 写回必须有来源、判断、去向
- 写回后必须能说明是否影响主脑
- 写回后必须能回滚

---

### 7. 哪些内容必须扔掉 / 降权

必须降权或移出有效区：

- 旧端口口径
- 旧版本固定提示
- 旧测试口正式化表达
- 退役区身份卡
- 暂存池旧 CURRENT / README
- 已被上位卡覆盖的重复长解释
- 无验收依据的一次性排障记录

保留但不得作为入口：

- `07-RETIRING`
- `08-IMPORT-STAGING`
- `99-DEFERRED`

验收标准：

- 不误删核心脑文件
- 不让旧材料参与当前判断
- 不让退役区反向污染正式区

## 二、阶段收口固定格式

任何阶段收口必须写：

### 已完成

列出已真实完成的动作。

### 未完成

列出仍未做完的尾巴。

### 下一步

只列一个最高优先项。

### 不能夸大

明确说明不能把当前成果说成什么。
