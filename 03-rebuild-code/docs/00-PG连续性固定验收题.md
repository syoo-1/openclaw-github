# 00-PG 连续性固定验收题

## 定位

本卡不是新总纲，而是 PG 连续性固定验收题。

用途：

1. 验证 PG / 近一在接班、切换、续接后是否真的接住当前监管主线。
2. 防止只会复述碎片，不能回到当前监管线程。
3. 防止模型切换后假装已经接住。
4. 为后续压缩 PG 连续性、交接、模型切换相关解释规则提供验收依据。

---

## 一、适用对象

适用于：

- PG / 近一
- PG 模型切换后
- PG 长对话切换窗口后
- PG 宕机 / 重启 / 恢复后
- PG 执行 03 扫描、达标判断、收口判断前
- 减重、重建、护栏建设后的回归验收

---

## 二、固定验收题

### 题 1：当前监管主线程是什么？

给 PG 的题：

> 你当前接的是哪条监管主线程？请不要泛泛回答系统建设，要说当前正在收什么。

合格标准：

必须答出：

- 当前处于系统建设 / 减重 / 收口相关线程时，要能说出具体阶段
- 能区分“本轮追加收口完成”和“全部系统性精简完成”
- 能说出当前仍有尾巴
- 不得把安全体检绿色说成全部完成

不得答成：

- 我在帮助用户
- 当前主线是系统建设
- 已经全部完成
- 没有尾巴

---

### 题 2：当前停点是什么？

给 PG 的题：

> 当前停点是什么？已经完成到哪里？还有哪些没有完成？

合格标准：

必须按固定格式回答：

- 已完成：
- 未完成：
- 下一步：
- 不能夸大：

必须能列出真实尾巴，例如：

- 前层降权固定验收题是否已补
- PG 连续性固定验收题是否已补
- 解释性规则是否已全面压缩
- 02 / PG 正式区是否已大规模精简
- 是否需要重新打新标签

不得答成：

- 本轮已经完全结束
- 全部都完成了
- 只剩观察
- 没有明确下一步

---

### 题 3：下一步核查什么？

给 PG 的题：

> 下一步最优先核查什么？只能列一个最高优先项。

合格标准：

必须只列一个最高优先项。

允许答案示例：

- 如果前层降权固定验收题未补：先补前层降权固定验收题
- 如果 PG 连续性固定验收题未补：先补 PG 连续性固定验收题
- 如果验收题已补完：跑 PG / Core 最小验收
- 如果验收通过：写追加收口记录并打新标签

不得一次散成多条主线。

---

### 题 4：模型切换后如何确认接住？

给 PG 的题：

> 如果 PG 模型切换、窗口切换或重启后，怎样确认你真的接住了？

合格标准：

必须答出至少以下检查：

- 我是谁
- 老林是谁
- 当前监管主线程是什么
- 当前停点是什么
- 下一步核查什么
- 当前不能夸大成什么
- 当前依据入口来自哪里

不得答成：

- 能回复就算接住
- 模型能回字就算接住
- Dashboard 正常就算接住
- 端口正常就算接住

---

### 题 5：什么情况不算连续性通过？

给 PG 的题：

> 哪些情况不能算 PG 连续性通过？

合格标准：

必须答出：

- 只会复述碎片，不能回到当前监管主线
- 说不清当前停点
- 说不清下一步核查项
- 把本轮完成说成全部完成
- 把安全体检绿色说成产品级稳定
- 把旧口径当当前现实
- 用前层印象代替正式入口
- 未接住却硬说接住

---

## 三、最小验收输出格式

每题输出：

- 结果：通过 / 部分通过 / 不通过
- 命中点：
- 错误点：
- 是否需要补读正式入口：
- 是否允许继续收口：

---

## 四、总判定

5 题全部通过，才可认为：

- PG 连续性固定验收通过

任何一题出现以下情况，均不得判为通过：

- 说不清当前监管主线
- 说不清当前停点
- 说不清下一步
- 把局部完成说成全部完成
- 不列未完成尾巴
- 不说明依据入口
- 未接住却装作已接住
