# 00-规则权威入口表

## 定位

本表不是新规则总纲，而是 03 规则读取导航表。

目的：

1. 明确不同问题优先读取哪张权威卡。
2. 防止局部卡重复解释上位规则。
3. 防止 PG / Core / 助手在多张卡之间来回绕。
4. 后续减重时，以本表作为“保留 / 合并 / 降权”的判断依据。

原则：

- 问当前现实，读 CURRENT / REALITY。
- 问长期原则，读 02 长期层。
- 问 PG / Core 主判、协同、模型、外部工具，读 03-Core-PG 上位卡。
- 问前层降权、后层优先、读取停止，读 03 总入口分流读取停止总卡。
- 问启动入口，读 03 启动总入口。
- 问 PG 自身身份与读脑顺序，读 PG 独立脑规则与 PG 身份卡。
- 局部卡只处理局部问题，不重复铺陈上位总纲。

## 九、减重判断规则

后续精简规则时按以下标准处理：

### 保留

- 当前现实
- 当前阶段
- 身份关系
- 主脑位置
- 读取顺序
- 同步 / 写回 / 回滚
- 验收判尺
- 上位权威卡

### 合并

- 多处重复解释同一原则
- 多处重复说明 PG / Core 分工
- 多处重复说明前层降权
- 多处重复说明模型不是主脑

### 降权

- 历史讨论
- 一次性排障过程
- 已被新规则覆盖的旧说明
- 旧端口、旧版本、旧阶段口径
- 只记录当时过程、不指导当前运行的文件

### 不直接删除

未经确认，不直接删除核心脑文件。  
先移入 retiring / thrown / deferred，再观察是否影响运行与验收。

## 十、总原则

规则减重不是为了少文件，而是为了：

1. 入口更清楚。
2. 判尺更清楚。
3. 冲突更少。
4. 运行体更不容易读错。
5. 后续 PG / Core 更容易按正确路径回答。

一句话：

保留权威入口，压缩重复解释，局部卡只写局部差异。
