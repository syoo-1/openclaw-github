# 03 主脑搜索 V2 设计卡

## 定位

本卡规定 PG / Core / 03 共用的主脑搜索机制。

主脑搜索不是普通全文搜索，而是：

1. 先判题。
2. 再分流。
3. 再按层搜索。
4. 读够就停。
5. 不把 runtime 噪音当成主脑依据。

当前搜索体系以 03 自有工具为底盘，OpenClaw 原生 memory / embedding search 只作为未来可评估增强层，不作为主权搜索依赖。

---

## 一、当前正式工具链

当前正式搜索链：

- `03-rebuild-code/tools/router-search-v1.sh`
- `03-rebuild-code/tools/brain-search-v3.sh`
- `03-rebuild-code/tools/memory-search-v1.sh`

职责：

| 工具 | 职责 |
|---|---|
| `router-search-v1.sh` | 搜索入口与题型路由 |
| `brain-search-v3.sh` | 正式脑层 / 03 / PG / Core 主脑搜索 |
| `memory-search-v1.sh` | 长期记忆索引搜索 |

旧工具：

- `03-rebuild-code/tools/brain-search.sh`
- `03-rebuild-code/tools/pg-brain-search.sh`

旧工具只作为历史兼容或旧调用说明，不作为当前 safety-check 的主依据。

---

## 二、搜索层级

### 1. 入口卡优先

先搜索短入口与当前状态卡，不直接扫全脑。

优先对象：

- CURRENT
- CURRENT-STAGE
- CURRENT-REALITY
- BRAIN-ENTRY
- IDENTITY
- READ-ORDER
- RULES
- 规则权威入口表
- 非入口目录说明
- 最终七件套收口验收卡

目的：

- 确认身份
- 确认当前阶段
- 确认题型
- 确认应该进入哪一层
- 避免一开始扫入大量噪音

### 2. 正式脑层搜索

候选范围：

- `~/System-Snapshots/02-brain`
- `~/System-Snapshots/03-rebuild-code/docs`
- `~/System-Snapshots/PG/brain`
- `~/SYOO1-PG/brain`
- `~/SYOO1-Core/brain`

搜索结果必须标记来源层级，例如：

- 02-mainline
- 02-longterm
- 03-rule
- pg-brain
- core-brain

### 3. 运行现场 / 扩展搜索

只有正式脑层不足时，才允许搜索运行现场。

可作为线索的范围：

- runtime/workspace
- status
- 必要 logs
- OpenClaw 原生 memory / embedding 结果

这一层只能作为线索，不能直接定案。

必须标记：

- 运行现场线索，不等于正式主脑依据。

## 四、输出格式

搜索输出必须省 token，不输出全文。

默认输出：

- 候选编号
- 层级
- 文件
- 命中关键词
- 关键行
- 建议动作

默认限制：

- 候选文件：20 个以内
- 每个文件关键行：3 到 8 行

如需阅读全文，由 PG / Core 再按需读取。

---

## 五、搜索模式与角色

搜索模式至少支持：

- AND
- OR
- 入口优先
- 正式脑层
- 扩展模式

默认模式：

- AND + 入口优先 + 正式脑层

角色参数：

- `--role pg`
- `--role core`
- `--role global`

含义：

- pg：优先搜 PG brain / PG status / 03 docs
- core：优先搜 Core brain / 02-brain / 03 docs
- global：搜 02-brain / 03 docs / PG brain / Core brain

## 六、OpenClaw 原生搜索边界

2026-04-28 初测结论：

OpenClaw 2026.4.14 原生 `openclaw memory search` 存在，但当前不纳入主脑搜索体系。

原因：

1. 当前主要索引 `$OPENCLAW_HOME/workspace/memory`。
2. 当前未确认可安全指定正式脑目录。
3. embedding deep probe 依赖 OpenClaw 自己的 `auth-profiles.json`。
4. 为启用它而恢复 `auth-profiles.json` 可能破坏当前密钥体系。
5. 它属于壳能力，不属于主权搜索底盘。

当前口径：

- 不接入 PG / Core 主脑搜索。
- 不作为 `brain-search-v3.sh` 的 native backend。
- 不为它恢复 embedding auth-profiles.json。
- 不让它参与正式脑判断。
- 未来除非证明它能安全、可控、可迁移地检索正式脑目录，否则不纳入主线。

---

## 七、失败边界

如果搜索没有结果，应明确说明：

- 未找到正式脑依据。

不得用前层印象补充成确定结论。

如果只找到运行现场线索，应明确说明：

- 只找到运行现场线索，未找到正式主脑依据。

---

## 八、验收标准

主脑搜索 V2 合格标准：

1. 能按 PG / Core / global 分角色搜索。
2. 能优先命中入口卡和正式脑层。
3. 能排除 runtime 噪音。
4. 能输出省 token 的候选线索。
5. 能明确区分正式依据与运行现场线索。
6. 不依赖 OpenClaw 原生搜索也能工作。
7. 可选接入 OpenClaw 原生搜索但不被其绑定。
8. 能被 PG / Core 共同调用。
9. 结构简单，可迁移，可维护。
10. 能通过 `safety-check-v1.sh` 中的搜索路由冒烟测试。

---

## 九、当前结论

主脑搜索 V2 当前以 03 通用工具链为正式底盘：

- `router-search-v1.sh`
- `brain-search-v3.sh`
- `memory-search-v1.sh`

PG / Core 不再各自维护独立搜索逻辑。

OpenClaw 原生搜索只能作为未来增强层评估，不能取代主权搜索底盘。
